# 来源学习工作区与 DeepSeek

## 使用

1. 启动 BiliLM，在资料库打开已完成的笔记。
2. 左侧 Sources 显示当前视频来源与文字预览。当前一个笔记对应一个视频，不跨库混合来源。问答和学习材料依据所选转录记录的校对稿；未人工修改时与原始稿相同。
3. 中间默认打开“来源问答”，自动显示当前来源提要。切换“文稿核对”可继续使用原稿、校对稿、可读稿、音频回放与导出。
4. 在中间底部点“DeepSeek 设置”，输入自己的 API Key 和模型名，点击“保存并启用 DeepSeek”。密钥无需发到聊天中。
5. 保存后自动生成来源总结，并可以多轮提问。最近 4 轮问答作为上下文；切换来源、版本或 AI 模式后重新开始问答。
6. 右侧 Studio 点“思维导图”。生成完成后先在下方“生成结果”出现卡片，点击卡片打开导图，再展开/折叠主题、点击子节点查看原句、缩放并导出 Markdown。“来源总结”同样保存为可打开的卡片。
7. “导出完整可读稿”下载标题、来源和整理后的全文，不附加原始时间轴。旧下载文件不会自动改变，请重新下载。原始时间轴仍在应用中保留，也可单独导出 SRT/JSON。

## DeepSeek 接入

2026-10-16 核对的[官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)列明固定接口 `https://api.deepseek.com/chat/completions`、`deepseek-flash` / `deepseek-v4-pro` 与非思考开关 `thinking.type=disabled`。界面默认填写 `deepseek-flash`，模型名可按账户实际可用模型修改；本轮没有比较这些模型的准确率或费用。

已有环境变量 `BILILM_LLM_URL`、`BILILM_LLM_MODEL`、`BILILM_LLM_KEY` 的兼容服务仍可使用。页面保存的 DeepSeek 设置优先，服务不需要因此重启。新设置保存到忽略目录 `data/llm-settings.json`；密钥仅供后端调用，读取配置接口只返回是否已保存，不返回密钥内容。文件内包含密钥，应作为本机私有配置保管，不随笔记导出。应用继续只允许本机访问；没有部署公共服务或增加跨用户密钥管理。

保存并启用即允许当前来源文字发往 DeepSeek，按其 API 规则计费。取消 AI 开关可以使用本地提要/检索；开关选择保存在当前浏览器。本地模式无需 API Key。

API Key 无效、余额不足、请求限流和参数错误分别显示可读失败提示。总结可以重试，已有缓存可复用，修改模型或校对稿后重新生成。没有密钥时，本地原文提要与结构导图明确标为非 AI，不冒充模型生成结果。

## 忠实性与边界

- 学习材料保存在独立 SQLite 缓存表，按来源文字、转录记录、类型、模式、服务与模型区分；不覆盖原始转录。
- AI 总结与导图使用 JSON 结构，引用索引必须指向有效来源段落；无效引用或无效结构不保存。引用有效不等于语义一定正确，也不表示听音验证。
- 问答中的时间引用只连接到当前来源中真实存在的标签。未返回可定位引用时提示手动核对。长来源问答超出全文预算时依据相关检索片段，并在界面提示范围。
- 自动总结/导图的来源 JSON 上限为 45000 字符。超限明确拒绝，不静默截断或声称总结了全文。后续可另做长文分层总结。
- 自动总结依据来源中的文字和数字；ASR 自身的错词仍可能进入总结。没有进行新的人工真值或准确率评测。

## 本轮验证

- **73 项后端测试通过**：包含原有 ASR/缓存/任务恢复，新增纯可读稿导出、来源变化使缓存失效、原稿保持不变、无效引用/JSON 拒绝、多轮上下文、密钥不回显及可读 API 错误。
- 生产构建和 TypeScript 检查通过。
- Headless Edge 实际页面验证：来源问答、引用定位、文稿标签与下载、可展开/缩放思维导图、节点来源、桌面/平板/手机与深浅色无横向溢出。
- 既有 UI 回归包含搜索、编辑后还原、音频播放、校对差异及修改日志、原稿不变与 SRT 导出。
- DeepSeek 请求协议使用 HTTP 模拟测试；密钥保存后自动总结、主题图使用浏览器拦截模拟，测试密钥及模拟结果没有写入实际应用。**尚未使用用户真实密钥调用 DeepSeek，也未产生付费调用。**
