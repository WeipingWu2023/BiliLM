# 准确率优先的架构审查与迁移计划

## 审查结论

现有 Phase 1 闭环成立。音频已按 16kHz 单声道 PCM 输入，原始时间轴已有不可覆盖保护；未发现必须重写网页、B 站接入或 SQLite 资料库的证据。small 的实测可读性不等于客观准确率；没有人工真值，因此不更换推荐默认。small 仅作为兼容旧行为的默认。

先完成的最小安全改动：保留媒体、独立转录 runs、版本与修改日志、ASR 配置记录、后端接口、SQLite worker 租约。CPU/GPU 是执行配置，不决定模型质量排序。网页只调用统一 API，worker 负责实际 ASR。

## 可保持不变

- Next.js/中文界面、蓝色与初音主题、三栏阅读。
- URL/BV/分 P 解析、平台访问限制、字幕优先、授权本地导入。
- FastAPI 同源 API、SQLite 资料库、原始 segments 数据库保护。
- 旧 TXT/SRT/Markdown 和人工整理稿编辑端点继续工作。
- FFmpeg 重采样；没有加入盲目降噪或换成激进 VAD。

## 需要重构并实施

1. 原有 `app.asr` 与 worker 紧耦合 → `ASRBackend` 标准适配边界。统一输入配置，统一 `{start,end,text,诊断字段}` 输出，底层 CUDA/CPU 对 API 格式透明。
2. 视频仅有一份原稿 → 追加不可变 `runs`。旧原稿、旧整理稿保留，迁移前备份 SQLite。新的人工校对/整理修改不能覆盖 raw。模型重转另建 run。
3. 临时音轨删除 → 新 run 保存原媒体与可播放 PCM、原媒体 SHA256。旧历史音轨已删除的事实不能被迁移“恢复”；需允许的重新获取或用户提供原文件。
4. 单 Windows msvcrt worker 锁 → SQLite `BEGIN IMMEDIATE` 原子认领、120 秒租约、20 秒心跳、唯一租约 token 写入围栏、到期恢复。避免新 worker 抢走仍活跃任务；Windows/Linux 使用同一 worker 入口。
   原稿、run 和任务完成状态在同一事务提交；播放文件按 job + lease token 命名，避免数据库围栏之外的媒体覆盖。已保留音轨优先从本地读取，无须再次请求平台元数据。
5. 缺执行记录 → 模型 revision/权重 SHA256、faster-whisper/CTranslate2/NumPy、FFmpeg、请求解码参数、实际语言、VAD 前后时长、硬件与耗时/RSS。峰值 RSS 是进程采样值，含模型与 Python 进程，不等于模型独占内存。
6. 未验证“AI 校对更准确” → 文字校对仅产生待人工接受的建议；保留理由、前后差异、时间映射和不确定标记。没有音频核对时绝不标成 audio-verified。

## 模块化流水线

来源获取 → 原媒体存档 → FFmpeg PCM → 语言配置/检测 → 主 ASR 后端 → 可选已有第二 run → 按重叠时间窗比较 → 待复核差异 → 人工/保守文本校对 → 可读排版 → 导出。

第二 ASR 不自动运行或下载。差异仅定位分歧，不通过多数票断定谁正确；需播放原音频和人工核对。字幕优先是另一来源路径，记录平台字幕 provenance，与同一音频人工真值独立评估。

## 后端候选与可复现评测

- faster-whisper small / medium / large-v3 / turbo：安装版本支持，现有 worker 的真实实现。大模型未缓存时必须显式允许下载；本轮不下载新大模型、不跑昂贵矩阵。
- SenseVoiceSmall：列为候选。它的识别、标记清理、长音频切分及时间对齐必须在适配层明确实现并测试；尚未安装运行时，不把它包装成已经可用的后端。统一 benchmark 可导入其按标准格式生成的预测，保留引擎/模型版本与时间粒度。
- 其他模型：同一契约提供预测后进入相同 scorer，而不是根据热门程度选默认。

评测按 Mandarin / Cantonese / zh-en-mixed 分层，固定相同音频、预处理和经人工听音验证的 reference。CER、适用的英文 WER、术语出现次数召回与假阳性、删除/插入/重复、时间边界误差、静音区错误输出、耗时和采样峰值 RSS 独立报告。文字 LLM 校对另列结果，不能与 raw ASR 合并或宣称听音验证。

用户已明确没有人工真值。本轮交付待核对样本/manifest、metric tests 和评测工具。未验证条目被评测器拒绝，不虚构百分比。模型默认决策要等每个语言层的实测结果、错误类型和资源成本审查。

## OCR 的位置

字幕、课件、代码截图 OCR 可以提出“这个术语在画面上出现过”的辅助证据，不能证明同一词被说出来。保留 frame 时间、OCR 文本、置信诊断与原图；只有重听对应音频/人工核对才能接受为 spoken transcript。暂不加入 OCR 依赖或自动抽帧，更不把 OCR 文本补进原稿。

## 云端部署（仅文档，不部署）

同一 API 和 JSON 转录结构继续使用；web/API、orchestration/store、worker 分进程。当前 SQLite 适合同一主机本地多个 worker，不用于跨机器共享盘队列。未来单独替换 jobs/store 接口为支持行级锁和租约的数据库；媒体改为对象存储；worker 根据 device capability 认领，不按开发机 CPU 限制模型候选。

正式公开部署前需要认证与每用户授权、租户隔离、配额/上传限制、加密与媒体保留策略、受控下载出网、签名媒体 URL、GPU 资源调度、Linux/CUDA/CTranslate2 兼容镜像、模型 revision 固定、失败监控和人工评测发布门槛。当前 localhost 的 Host/Origin 检查不是公网安全系统。暂不添加 Redis、Kafka、Kubernetes、自动云账号或部署。

## 迁移次序与验收

1. 审计和备份 → 兼容旧 schema；旧原稿的 SHA256 和文字不变。
2. 后端配置/媒体归档 → 缓存 small 的真实短片重转验收，禁止自动大模型下载。
3. 追加 runs/校对/日志/播放与各版本导出 → 原稿不可覆盖和时间索引测试。
4. 租约/心跳/围栏 → 并发认领、到期恢复、旧 token 拒绝提交；单机多 worker，不模拟已完成云端测试。
5. 人工真值模板/分语言 scorer → 已知编辑距离和时间偏差 fixture 验证，未人工审核的数据不计准确率。
6. UI 与 MVP 回归 → 生产构建、桌面/手机阅读、缓存/编辑/导出、真实本地小模型流程。
